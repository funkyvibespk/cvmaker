# DOCX visual acceptance set

These eight Word files were generated by the current `generateResumeDocx` implementation from validated synthetic canonical resume data. They contain no real user's information. The profile picture is a synthetic portrait illustration from `tests/fixtures/profile-photo.png`.

| `08-us-letter-comprehensive.docx` | US Letter | Same comprehensive English content as file 2 | Confirm US Letter paper and default margins. |

The default design margins are 14 mm top/bottom and 16 mm left/right. The generated section sizes are A4 210 × 297 mm and US Letter 215.9 × 279.4 mm.

## Microsoft Word review procedure

1. Open each file in desktop Microsoft Word. Use **View → Print Layout** and set zoom to **100%**. Read the page count from Word's status bar; enable **Page Number** there if it is hidden.
2. For every page, check that text is readable, headings remain with their next entry, bullets are consistently indented, dates align at the opposite edge from entry titles, and no text or photo clips or overlaps.
3. In **Layout → Size**, confirm A4 for files 1–7 and Letter for file 8. In **Layout → Margins → Custom Margins**, verify 14 mm top/bottom and 16 mm left/right.
4. For file 1, record whether it fits on one page at the intended font size. Do not use Word's shrink-to-fit or reduce type to force it onto one page.
5. For file 3, verify all 18 role headings and the first and last achievements remain present. Check for blank pages, stranded headings, excessive gaps, or awkward short-entry splits.
6. For file 4, verify the image is embedded and keeps its portrait aspect ratio; it should not depend on an internet connection.
7. For files 5 and 6, check the whole page at 100% and inspect mixed Arabic/Urdu plus Latin text closely. Confirm shaping, line direction, punctuation, bullets, and link order in the installed Word fonts.
8. Compare files 2 and 5 with the matching English and Arabic resume samples in the local builder preview and PDF. Confirm the same visible sections, entry order, text, and accent hierarchy. Urdu Word rendering is a separate check because the builder does not provide a matching Urdu sample fixture.
9. Record the page count and any defect for every filename before accepting visual quality. If a defect appears, retain a copy of the affected DOCX and describe the page and element; do not overwrite the supplied test file.
